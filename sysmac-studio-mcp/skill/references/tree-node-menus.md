# 工程树节点类型 × 右键菜单（全量实测）

作者：hoverwu ｜ 实测日期：2026-11-06 ｜ 基线：Sysmac Studio V1.68 64bit（`1.68.0.64010`）、Win11、125% DPI

**样本工程**：某库工程（窗口标题形如 `<库工程名> [库] - new_Controller_0`，离线、未登录控制器），工程树 84 个节点，`TVM_GETCOUNT=84`。

**怎么测的**：`scripts/ss_uimap.py treectx auto <out> --fit <path> <path> ...` 对每个路径

1. 用 `TVM_SELECTITEM(TVGN_CARET)` + 真实 `VK_RIGHT` 逐级展开祖先（`TVM_EXPAND` 在 Sysmac 只对根节点有效）；
2. 用远端 `TVM_GETITEMRECT` 算出行中心点，`row_hit` 真实点击后由树自己回读句柄证明点中了；
3. 右键弹菜单 → UIA 遍历弹层（独立顶层窗口，类 `WindowsForms10.Window.20808.app.*`，按类名匹配、句柄不硬编码）→ `Esc` 关闭；
4. 一条通道没反应就换下一条：`RCLICK`（行中心）→ `RCLICK2`（同行 +80px，避开展开三角）→ `VK_APPS`（仅当 `GetGUIThreadInfo` 说树真的持有键盘焦点）。
5. 三条通道全空 → 判定该**节点类型没有上下文菜单**，并全屏截图留证（`shots/miss_<path>.png`）。

原始记录（**不随 Skill 发布**，需要时按 §4 重跑）：`tctxA.txt`（0～0.6）、`tctxB.txt`（0.7～1.0.1.0）、`tctxC.txt`（1.0.1.1～1.2.1）、`tctxD.txt`（根与两个容器复测）、`tctxE.txt`/`tctxF.txt`（带节点名的复测，跨两次运行项目集合与可用态完全一致）。节点名来自 `ss_uimap.py treelabels`（见 [project-tree.md §2](project-tree.md)）。

### 2.3 POU 实体

三种形状，差别都在细节：

| 路径 / 节点 | 形状 |
| --- | --- |
| `1.0.1.x` 功能（FC_TimeTransfer 等 4 个）· `1.0.2.x` 功能块（44 个 FB） | `编辑(E)`✓ `剪切(T)`✓ `复制(C)`✓ `带有副本复制`✓ `选择并复制多个项目`✓ `粘贴(P)`✗ `删除(D)`✓ `删除多个项目`✓ ‖ `重命名(R)`✓ `在上方插入`✓ `上移``下移`（见下）`安全性(U)`✓ `属性`✓ |
| `1.0.0.0` 程序实体（`PRG_Example`） | 上面那套 **+ `添加`✓ + `调试用设置`✓ − `编辑(E)`**（15 项）——它是容器型实体，自身没有可编辑体，编辑在子节点上 |
| `1.0.0.0.0` 程序内的 POU（`PrgMain`） | `编辑(E)`✓ `剪切(T)`**✗** `复制(C)`✓ `带有副本复制`✓ `粘贴(P)`✗ `删除(D)`**✗** ‖ `重命名(R)`✓ `在上方插入`✓ `上移`✗ `下移`✗（**10 项**：没有 `选择并复制多个项目`/`删除多个项目`/`安全性`/`属性`/`添加`） |

`上移`/`下移` 的可用态只由**在同级里的位置**决定，实测 6 个样本全部吻合：第一个（`1.0.1.0`、`1.0.2.0`）→ `上移`✗；最后一个（`1.0.1.3`、`1.0.2.43`）→ `下移`✗；中间（`1.0.1.1/2`、`1.0.2.7/15/21/30`）→ 两个都✓；唯一子节点（`1.0.0.0`）→ 两个都✗。

`PrgMain` 的 `剪切`/`删除` 被禁是语义正确：程序主体删了程序就空了。**要搬整个程序，搬 `1.0.0.0`，不是搬 `1.0.0.0.0`。**

## 3. 通用规律（可以直接拿来写自动化）

1. **凡是"实体"节点都有 `复制(C)`**（POU、POU 容器除外的是配置分支）；**凡是"配置"叶子只有 `编辑`**，没有 `复制` —— 这就是配置搬不动的界面层原因。
2. **`粘贴(P)` 本次全灰**：采集时剪贴板是空的（脚本刻意不复制任何东西，纯只读）。要判断某节点能不能接收粘贴，**先复制一个同类实体再看这一项**，不能拿本表的 `✗` 当结论。
3. `添加` / `在上方插入` 是**带子菜单**的容器项：UIA 里它们是 `MenuItemControl` 但 `GetExpandCollapsePattern` 拿不到，所以脚本只打印出父项、没有列出子项（记录里的 `menuitems=` 计数会**大于**打印行数，差额就是这些没展开的子项，例如 `1.0.0.0` 计数 23 / 打印 16 行）。要子菜单内容得手工展开或走"点父项 → 抓新弹层"（待办，见 §5）。
4. 弹层是**独立顶层 HWND**，类名固定 `WindowsForms10.Window.20808.app.0.*`；跨进程分两次调用打开再读是读不到的，必须在同一个进程里"右键 → 读 → Esc"（[project-tree.md §4](project-tree.md) 的同一条约束）。

## 4. 复现命令

```bash
# 节点名（安全读法：TVM_GETITEMW + 远端 TVITEMW/文本缓冲）
python <SKILL_DIR>/scripts/ss_uimap.py treelabels <pid|auto> logs/labels.txt

# 一批节点的右键菜单（--fit 把窗口滑回屏内，否则客户区底在屏外，下面几行点不到）
python <SKILL_DIR>/scripts/ss_uimap.py treectx <pid|auto> logs/tctx.txt --fit 0.0 0.4.0 1.0 1.0.2.21
```

必须**提权**运行（Sysmac 若以高权限启动），且**不能锁屏**（要真实鼠标/键盘）。

## 5. 已知缺口（别当成"已测完"）

- **在线状态**（连接控制器 / 仿真运行）下的菜单没测：`MC监测表`、`应用驱动数据到轴设置`、`传送Cam轮定义值`、`监视DB连接服务`、OPC UA 的 4 项安全设置此刻全灰，不知道多了什么项、也不知道会不会少项。
- **多选用右键**（选中 2 个以上 POU 再右键）没测，`删除多个项目` 的可用态可能变化。
- `添加`/`在上方插入` 的**子菜单项**未列出（§3.3）。
- 其他工程类型（普通控制器工程、带安全的 CPU、`[库]` 之外的工程）根结构不同，**下标会变**；用之前先 `treelabels` 建立本工程的基线路径表。
